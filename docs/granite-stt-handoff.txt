# GRANITE STT — Resumo para nova sessão

## Objetivo
Ferramenta nova "Granite" no SIG Android (card amarelo na tela Ferramentas), rodando o modelo
**Granite Speech 5.0 TurboCTC** (ibm-granite/granite-speech-5.0-470m-turboctc) localmente via ONNX.
Seguir o padrão do Whisper. Modelo F32 puro (~1,9 GB), backends CPU / GPU(NNAPI) / NPU(NNAPI).
Modelo é EN-only (4.1 multilíngue fica para depois).

- NÃO aumentar o APK (APK < 10 MB) — libs nativas ficam no R2, como FFmpeg/Whisper.

- Baixar do Cloudflare R2 (bucket sig-android). Upload feito na subpasta `models/`.
- Diálogo com barra de progresso igual ao Whisper.

## Erros já corrigidos (causa → fix)
1. "frontend_config sem deltas" → parser lia número; JSON tem `"deltas": true` (bool). Fix: parser bool.
2. Loop "pede download de novo" → Activity procurava nome errado (sem `-ext`). Fix: GRANITE_MODEL_FILE alinhado + packageComplete(8 arquivos).
3. "nada acontece" após transcrever → status invisível (gone) + ALL_OPT lento. Fix: status visível + NO_OPT.
4. Fallback GPU/NPU silencioso → agora pergunta se quer CPU (diálogo).
5. **Principal**: `UnsatisfiedLinkError: libonnxruntime4j_jni.so not found` → onnxruntime-java no Android ignora onnxruntime.native.path e usa System.loadLibrary (só namespace do APK). Fix em 2 partes:
   a) NativeDependencyManager.registerNativeLibraryDir() registra dir R2 no DexPathList.nativeLibraryPathElements via reflexão (construtor NativeLibraryElement(File)).
   b) SigApplication.attachBaseContext() chama activateIfInstalled ANTES dos ContentProviders (o ORTTelemetry rodava antes e falhava).
   VALIDADO: libs carregam OK no logcat.
