1. FLUXO DE BUILD (caminho OFICIAL, sem instalar nada no PC)
════════════════════════════════════════════════════════════════
No servidor:
  1) git clone --depth 1 llama.cpp -> /root/llama-cpp-npu (pin: conferir
     commit == 5e03bdd do master; registrar o hash REAL clonado).
  2) docker pull ghcr.io/snapdragon-toolchain/arm64-android:v0.7 (oficial;
     inclui NDK r28b + OpenCL SDK + Hexagon SDK 6.6.0.0).
  3) Build dentro do container:
       docker run --rm --platform linux/amd64 -u root \
         --volume /root/llama-cpp-npu:/workspace \
         ghcr.io/snapdragon-toolchain/arm64-android:v0.7 bash -c '
           cd /workspace
           cp docs/backend/snapdragon/CMakeUserPresets.json .
           cmake --preset arm64-android-snapdragon-release -B build-snapdragon
           cmake --build build-snapdragon -j 20
           cmake --install build-snapdragon --prefix pkg-android/llama.cpp'
  4) Saida esperada: pkg-android/llama.cpp/{lib,bin} com libggml-hexagon.so,
     libggml-htp-v73/v75/v79/v81.so, llama-cli, llama-bench, e (se o preset
     gerar) test-backend-ops.
  5) scp do pacote de volta ao PC (dezenas de MB).
