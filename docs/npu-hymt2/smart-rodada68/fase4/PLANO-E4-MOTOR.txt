2. SEMANTICA (design SS1 — nao negociavel)
------------------------------------------
- NPU: prefill E geracao predominantemente no HTP0; ops nao suportadas explicitas.
- Smart (X): prefill no HTP0 -> ponte de estado -> geracao no device X
  (X=OpenCL "GPUOpenCL" ou Vulkan "Vulkan0"); SEM replay integral; tok1 amostrado
  UMA vez na origem e emitido UMA vez; jamais rotular NPU+CPU como Smart.
- Fallback nunca silencioso: indisponivel => erro claro com diagnostico.

3. DESENHO DO MOTOR (port do probe, adaptado ao monolito)
---------------------------------------------------------
3.1 Device lookup (substitui is_gpu_device/find_gpu_device):
    - nomes reais: "HTP0" (NPU), "Vulkan0", "GPUOpenCL", "CPU".
    - nova funcao find_device_by_name(kind) + device_matches_backend estendido
      ("htp" no kind NPU).
3.2 NPU (kind 3):
    - dev = dev_by_name("HTP0"); ausente => erro "NPU (HTP0) indisponivel" (nao silencioso).
    - 1 contexto: devices={dev,0}, n_gpu_layers=-1 (igual GPU hoje).
    - setenv ADSP_LIBRARY_PATH=<dir das libs nativas> ANTES do primeiro uso do HTP
      (o FastRPC acha o skel libggml-htp-v81.so por ele; seed do probe.cpp:130-133).
      Dir: derivado do modelPath/dir das libs do pacote (a confirmar na interface).
3.3 Smart (kinds 4/5):
    - 2 contextos do MESMO modelo: cs (HTP0) + cd (GPUOpenCL/Vulkan0 do kind).
      Estrategia A do design (2 contextos + export/import) — validada no probe.
    - Fluxo de geracao (ordem R4-B, do run_bridge):
      (0) reset por pedido (hymt2_begin_fresh_request) nos dois contextos;
      (1) prefill no cs em CHUNKS de 128 (chunk_plan portado; nt>128 => lotes;
          erro em chunk => ABORTA);
      (2) export: sz=llama_state_get_size(cs); got=llama_state_get_data(...);
          gate got==sz (senao erro export_invalido);
      (3) tok1 = sampler_sample(cs) — MESMA cadeia de sampler do produto;
          EOG em tok1 => erro "EOG_tok1_sem_handoff" (gate R4-B);
      (4) emit tok1 UMA vez (streaming) e contar emissao;
      (5) import: rd=llama_state_set_data(cd,...); gate rd==st.size();
      (6) pos gate: seq_pos_max(cd)==nt-1;
      (7) loop: decode(cd) do ultimo token -> sample -> emit -> EOG/cap.
      Espelho teacher-forcing: NAO em producao (so diagnostico opcional/anotado).
    - Memoria: 2x pesos (~1,1GB cada)+KV — risco R3 do design: medir no aceite;
      carregamento sob demanda (smart so quando escolhido) e liberado no unload.
3.4 Interface com o Kotlin:
    - generate mantem assinatura; kind 3/4/5 entram pelos mesmos parametros.
    - Capability NPU para a politica: nova funcao JNI hasNpu() (dev_by_name HTP0
      != null) para o runtime; STQ continua barrado por supportsNpu (modelo).
3.5 chunk_plan: portar chunk_plan.h para llama-jni/ (helper PURO, mesmo contrato:
