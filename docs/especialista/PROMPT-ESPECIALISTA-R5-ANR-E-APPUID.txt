========================================================================
5.1 O que foi construido: projeto Android minimo C:/npu-probe (package
    br.gov.sp.pcsp.npuprobe, ID distinto; NAO reinstala/altera o SIG), JNI
    proprio (probe.cpp) chamando a API publica ggml; libs do build
    "probe-min" no servidor (GGML_OPENCL=OFF/VULKAN=OFF: ggml, base, cpu,
    hexagon, htp-v81; NEEDED limpas exceto sistema); ADSP_LIBRARY_PATH setado
    no JNI; APK 2.6 MB, extractNativeLibs=true.
5.2 Iteracoes (achados de empacotamento relevantes para integracao):
    - libggml.so upstream tem DT_NEEDED de libggml-opencl.so -> a cadeia
      vendor (libOpenCL -> libcutils) NAO e carregavel de dentro de um app;
      stub nao satisfaz VERNEED; solucao: build proprio SEM OpenCL (feito);
    - conclusao: runtime NPU de produto deve evitar DT_NEEDED de cadeia
      vendor; usar loader proprio (como android-opencl-loader.cpp do SIG).
5.3 RESULTADO FINAL no device (app-UID nao-root; controle positivo incluso):
    | teste                                       | resultado |
    |---------------------------------------------|-----------|
    | probe roda como app (JNI, logcat)           | OK |
    | controle dlopen("liblog.so")                | OK |
    | dlopen("libcdsprpc.so") por NOME            | FALHOU (dlerror null) |
    | dlopen("/vendor/lib64/libcdsprpc.so")       | FALHOU |
    | HTP0 registrado para o app                  | NAO (somente CPU) |
    - libcdsprpc.so ESTA listada em /vendor/etc/public.libraries.txt
      (verificado read-only) e mesmo assim o app-UID nao a carrega; o NULL
      sem dlerror e a assinatura do bionic para bloqueio de namespace.
    - No ADB shell (root/ksu) o mesmo dlopen funciona (todos os testes HTP
      R1-R4). => DIFERENCA SHELL-vs-APP EMPIRICAMENTE PROVADA.
5.4 Consequencia: integracao NPU via backend hexagon direto NAO e elegivel
    a app normal neste CPH2747/ColorOS; precisaria de caminho OEM
    (whitelist/assinatura/sistema) ou mecanismo suportado do fabricante.
    O app SIG (QNN) tambem nunca habilitou execucao HTP como app — coerente.
