A pergunta: por que a ACT (q8_0 tiled!) nao volta ao host hoje?
- A quantizacao roda NO SKEL (DSP!): kernel hvx-mm-kernels-tiled.h:1205;
- o DST vai para mmctx->vtcm_src1 (VTCM — mem DSP, host NAO ve!);
- os spads (htp-ctx.h:33) tambem sao VTCM ("pointer to an area in vtcm"!);
- os unicos canais host<->skel: tensores (DMA/fastrpc!), SHM do batch
  (descritores+traces!), kparams.

O MECANISMO PARA LEVAR A ACT AO HOST (mapeado peca a peca!):
1. ggml_hexagon_shared_buffer (ggml-hexagon.cpp:339): {sess, base, size,
   fd, mapped, pinned} + mmap() via fastrpc_mmap(domain_id, fd, base, 0,
   size, flags) — a memoria dos fds E MAPEADA (o DSP a enxerga!);
2. add_buffer(ggml_hexagon_shared_buffer*) (ggml-hexagon.cpp:1686): registra
   um buffer no batch (b_map por fd!); cada buffer = htp_buf_desc{base,
   size, flags, fd} (htp-ops.h!); n_bufs++ (HTP_OP_MAX_BUFS!);
3. h.bi = add_buffer(sbuf) (L1754!): um tensor aponta o buffer pelo indice bi;
   h.data = t_offset (L1756!) = offset no buffer ("data pointer on the NPU"!);
4. SHM por batch (ggml-hexagon.cpp:1925+): dbuf.size = b_size (buf descs!) +
   t_size (tensors!) + o_size (ops!) + p_size (profs!) + tr_size (traces!);
   dbuf.flags = FLUSH_SENDER|INVALIDATE_RECIPIENT (coerencia!);
5. NO SKEL: struct htp_mmap {size, base (endereco DSP!), fd} (htp-ctx.h!);
   o skel mapeia os fds (HAP_mmap — main.c:167/175/212/838!) -> mmap[bi].base;
6. o op_desc (htp-ops.h!): {opcode, flags, params[16], kernel_params[16],
   src[4], dst[4]} — kernel_params = "generic blob for host-precomputed
   parameters" (a LIB os preenche no precompute do matmul!);
7. o kernel (L1205): dst_data = mmctx->vtcm_src1 + dst_row_size*ir_first;
   htp_mm_q8_0_tiled_row_size(6144) = 192 x 1152 (HTP_MM_ACT_TILE_SIZE_Q8_0 =
   1152!) = 221184 B/row (B=1 => 1 row => a ACT completa!);
8. o worker (QUANTIZE_IMPL L814!): src = octx->src[1] (o F32 do host — DMA!),
   dma_make_ptr(dst, src) (dma-queue.h:144!) para as copias.
