B. HOST — ARMAMENTO E VÍNCULO NÃO SÃO SEGUROS

C. DSP — ÍNDICES DISTINTOS, BOUNDS E COBERTURA
C.1 diff:63–64 interpreta o índice do batch como slot ctx->mmap[bi].
A referência htp/main.c:804–816 procura mapping por FD; :833–861 ocupa
qualquer slot livre; :865–899 reutiliza mappings; :903–908 resolve tensor
pelo DESCRITOR bufs[bi].base, já traduzido, não por ctx->mmap[bi].
Executei reuse_buf da referência + guard R45 sobre mappings controlados:
 bi do batch=1, FD99 reutilizado no slot7; o patch escolhe slot1 de outro
 buffer. SELECTED_MATCHES_RESOLVED_DESCRIPTOR=0.
Isso demonstra que as duas numerações não são intercambiáveis nessa
referência. Não inventar API nem presumir que a coincidência no primeiro
batch é contrato. Confirmar prep_op_bufs/reuse no candidato e usar sua
resolução oficial por descritor/FD. A bounds correta no buffer ERRADO
continua sendo incorreta.

C.2 Guard apenas exige mmap.size !=0. O memcpy copia
row_size*(ir_last-ir_first), com offset row_size*ir_first, sem verificar
fim<=capacidade, sem conferir base válida e sem produtos overflow-safe.
Contraprova real do fragmento: mapping declarado8192, row221184, escrita
passa212992 bytes da capacidade declarada. O armazenamento físico do teste
é maior, com sentinela: nenhum acesso fora da alocação foi provocado.
B2 precisa442368, maior que buffer fixo262144. Cálculos conferidos por
ferramenta. São contraprovas de contrato, não corrupção DSP observada.

C.3 op_matmul limpa/seta o ponteiro, mas a referência limpa o octx uma vez
por batch (main.c:1030–1046); entre ops limpa scratchpads, não o novo
ponteiro (main.c:963–971). Dispatch fused/ID usa caminhos próprios e pode
reutilizar a macro instrumentada. Risco de pointer stale entre operações:
confirmar no candidato e zerar/desarmar no limite correto de TODAS as ops.
Não presumir que uma op não selecionada nunca consultará o ponteiro.

C.4 Quantizador ROW/tiled instrumentado não prova captura BLOCK/flat/HMX.
A referência matmul-ops.c:843–849 mostra macro inclusive F32/F16; :851+ tem
workers BLOCK separados. O HMX desvia no op_matmul. Sem branch registrado,
0bytes/código não chamado é NOT_CAPTURED, não sucesso com bytes antigos.
O nome de trigger mmtest:q4k é rótulo da suíte: provar que a operação
capturada é Q6_K, K6144/N2048/B1 e usa o actfloat R39 íntegro.

3. CORRIGIR DSP — RESOLUÇÃO REAL, BOUNDS E CONTEXTO
Não usar ctx->mmap[batch_bi] como sinônimo de bufs[batch_bi].base. Resolva

ou FD diferente = recusa consumida ANTES de memcpy; sem abort genérico que
possa derrubar DSP/aparelho.

REAL. A captura alvo B1 precisa221184 payload bytes somente se a rota/formato
confirmados produzirem esse row_size. Se adicionar header/alinhamento,
contabilizá-los; não confundir payload com buffer total. B2/grandes shapes
recusados ou alocados conforme contrato verificado, nunca overflow no256KiB.
Validar source interval/lifetime, rows e strides, src/dst não sobrepostos,
base válida e fim<=size nos DOIS lados. Nenhum sentinel parcial é CAPTURED.

Inicialize/limpe estado de dump no início/fim de TODAS as operações relevantes,
inclusive fused/ID/QKV/FFN/nãoalvo e caminhos HMX/BLOCK/flat. Só caminho
selecionado pode copiar; demais retornam NOT_CAPTURED ou passam sem dump,
sem herdar ponteiro. Documentar cobertura. Operação alvo que não chegou ao
helper escolhido não emite COMPLETE lendo bytes stale.

static inline bool reuse_buf(struct htp_context *ctx, uint32_t *m_reuse, struct htp_buf_desc *b) {
    b->base = NULL;

    for (uint32_t i=0; i<HTP_MAX_MMAPS; i++) {
        struct htp_mmap *m = ctx->mmap + i;
        if (m->size && m->fd == b->fd) {
            b->base   = m->base;
            *m_reuse |= (1 << i);

    return false;
}
